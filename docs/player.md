# Player, mpv and queue

Seaglass implementation notes, read on demand (index in [`CLAUDE.md`](../CLAUDE.md)). The player architecture (single actor, queue, 2-entry window) is summarized in `CLAUDE.md`.

## mpv

- Launched by the app with `--no-config --include=<seaglass.conf>` so as to **never** load the user's personal video mpv config.
- Base options: `--idle=yes --no-video --input-ipc-server=\\.\pipe\seaglass-mpv-<app pid>-<random> --ao=<device::AO> --gapless-audio=weak --prefetch-playlist=yes`. `--ao` is `wasapi` on Windows and `pipewire,pulse,alsa` on Linux (#17, mpv takes the first one that opens; on Linux the pipe is a Unix socket in the temporary folder). The pid in the pipe name prevents connecting to an orphan mpv from a previous launch, the random part prevents another process from creating it before mpv.
- Tauri quits without running destructors: mpv is killed explicitly on `RunEvent::Exit` (`mpv::process::ProcessGuard`). On a crash, the Job Object (see below) stops it, or `PR_SET_PDEATHSIG` on Linux.
- `media-controls=no` and `input-media-keys=no` in `seaglass.conf`: otherwise mpv publishes its own "mpv" SMTC session, which grabs the media keys (cause of issues #6 and #27). Only Seaglass's session must exist.
- `audio-params` becomes `null` at each end of file and is not sent again if the next track has the same format: a `null` is ignored, the output is only cleared on `idle-active` (#12, `PlayerState::set_output`).
- **Exclusive mode** (0.5.0, #245, `mpv/exclusive.rs`, `player/exclusive.rs`): setting `PlaybackSettings::exclusive` (off by default, no effect outside Windows: `exclusive::supported`, and hidden in Settings › Playback outside Windows through the `exclusive_available` command, #17), passed as `--audio-exclusive` at launch (and on the #255 restart) and set live through `Op::Exclusive` → `set_property audio-exclusive`: mpv reopens the output **without interrupting the track**. Normalization is suspended (`Normalizer::bypass`, the setting stays saved and grayed out in Settings › Playback), no gain set; the equalizer (#428), however, stays applied (the user's choice: allowed in exclusive mode, the signal path reports it); no forced `audio-samplerate`. **Software volume kept** (the user's choice in #245): the verdict becomes "Software volume" outside 100 %, as in shared mode; shortcuts and wheel unchanged. Failure to open in exclusive mode (device taken by another app): `end-file` `error` `audio output initialization failed`, on toggling as well as on loading → `on_exclusive_failed`: `stop`, pause on the track, toast; **no fallback** to shared mode or to another device (Play retries). `PlayerState::exclusive` and `device_format` (`audio-out-params`, observed, `null` ignored like `audio-params`). Verified with mpv 0.42 (`cargo test live_exclusive -- --ignored --nocapture`, sine at −40 dBFS, default output): in shared mode `audio-out-params` = `float` 48 kHz (Windows mix, even for a 44.1 kHz stream); in exclusive mode `s16` 48 kHz on this device, which refuses 44.1 kHz (mpv tries formats and rates, `-v` lists them); another player in exclusive mode on the same device fails. **50 ms exclusive buffer** (`wasapi-exclusive-buffer=50000` in `seaglass.conf`, #308): by default mpv takes the device's default period (10 ms), but the user's USB Focusrite only signals the WASAPI event every ~22 ms (its real period, visible in shared mode: `Buffer frame count: 1056 (22000 us)`): under-run on every cycle, crackles and repeated bits. Measured with `--msg-level=ao=trace` (44.1 kHz sine, 10 s): 10 ms and `min` (3 ms) → permanent under-run, 20 ms → 18, 40 / 50 / 100 ms → 0. 50 ms keeps a margin without noticeable latency (volume is applied before the buffer); live toggling rereads the option. On this Focusrite, exclusive mode only accepts 48 kHz (the rate set in the interface): a 44.1 kHz stream is resampled by mpv there, and the signal path reports it (it compares with the format opened on the device).
- Observed properties: `playlist-pos`, `time-pos`, `duration`, `pause`, `paused-for-cache`, `audio-params`, `current-ao`, `idle-active`, `audio-device-list`, `audio-out-params`, `demuxer-cache-time`. Event: `end-file`. Properties written without being observed (the actor's state is authoritative): `volume`, `mute`, `demuxer-max-bytes`, `demuxer-max-back-bytes`, `audio-device`.
- **Cache**: `cache=yes` and `cache-on-disk=no` in `seaglass.conf` (memory only). The size comes from the `playback.settings` setting (`mpv/cache.rs`, `player/settings.rs`: 32 / 64 / 128 / 256 MiB, default 64, back buffer = a quarter), passed on the command line at launch then applied live through `set_property`. Effective as soon as playback consumes packets (when paused, the full demuxer stays asleep); verified through `cargo test live_cache_resize -- --ignored --nocapture`. With the next track preloaded, memory can reach twice the chosen size.
- **Cache indicator** (0.5.76, #453): `demuxer-cache-time` (observed, a number: position in seconds up to which the demuxer has read the current file; lighter than the `demuxer-cache-state` object) → `Event::Cached`; on Android, Media3's `bufferedPosition` sent with each position (`"type":"cached"`). `PlayerState::cached` only moves by one-second steps, on a decrease (new track, seek) or at the end of the track (`set_cached`, tested), and counts with `time_pos` within the ~4 Hz limit (`differs_only_by_time`); reset to 0 when a track loads. `PlayerState::next_ready` = next track preloaded. UI: `.cached` band under `.fill` in `Progress.svelte` (`--cached`), and a `.cache` line under the Decoding node of `SignalPath` ("in memory up to 2:40", "track in memory", "next ready", `cacheLabel` in `format.ts`, tested), absent from the compact version. Pitfall (#498): showing the lead `cached − time_pos` gives a sawtooth, because the cache advances by DASH segment (several seconds at once) and the position continuously; so the position reached is shown, which only goes up while filling. With the default cache (64 MiB), a 16/44 FLAC track (~25-30 MB) fits entirely a few seconds after the start: the indicator mostly matters in hi-res or on a slow connection. Preview: `?cached=whole|<seconds ahead of the position>`, `?nextready`.
- **Volume normalization** (#82, `player/normalize.rs`, pure tested logic): setting `PlaybackSettings::normalization` = `off` (default, validated by the user) / `track` / `album` (album gain, otherwise the track's). Gain from the API (`Stream::gain`, ReplayGain from `playbackinfopostpaywall` of the stream actually played, hi-res edition included), **limited by the peak** (`gain ≤ −20·log10(peak)`, never clipping), bounded to [−24, +12] dB, rounded to the hundredth; zero or unknown → no filter. Applied as a **file option** of `loadfile` (`options` = `start=…,af=volume=volume=<g>dB`, flags `replace` or `append`): the preloaded track does not affect the current one. Setting change: `set_property file-local-options/af` on the current track (reset at the end of the file; `options/af` shows the value in force, it is not a leak), then the preloaded one is removed to be reloaded with its gain. Verified with mpv 0.41 and 0.37 (`cargo test live_per_file_af -- --ignored --nocapture`, short real playback of a sine at −40 dBFS, volume 30): `af` = −6 dB on the current track, −12 dB on the preloaded one only after the gapless switch, `af=[]` on a file loaded without option; output stays `s16`. `PlayerState::normalization` (gain applied in dB or `null`) → verdict "Volume normalized" (never bit-perfect, mute stays the priority), "RG −6.5 dB" under mpv. Settings › Playback: `.normalization-modes` / `.normalization-mode` (with `.cache-sizes` / `.cache-size` / `.hires-mode`). In exclusive mode (#245), this setting is grayed out and no `af` is set. Preview: `?normalization=track|album`.
- **Parametric equalizer** (0.5.81, #428, `player/eq.rs`, `player/autoeq.rs`, `mpv/filters.rs`, pure tested logic): setting `PlaybackSettings::equalizer` = `{enabled, active, profiles}` (off by default; 32 profiles, 20 filters per profile at most). Profile = `id`, `name`, `preamp` (dB, `null` = automatic: `−max(positive gains)`) and `peaking` / `lowShelf` / `highShelf` filters (`freq` 20 Hz–20 kHz, `gain` ±20 dB, `q` 0.1–10), bounds checked on deserialization (`try_from`): an invalid profile is refused by `set_playback_settings`; an `active` that no longer designates any profile becomes `null` without making the settings rejected. **A single `af` chain per file**: a file-local `af` value (normalization's) replaces the whole global list, an equalizer set through `af set` would be lost on every normalized track. `engine::Filters { gain, eq }` goes with `Op::Play`, `Op::Preload` and `Op::CurrentFilters` (formerly `CurrentGain`); `mpv::filters::af_value` builds `volume=volume=<gain + preamp>dB,bass=f=…:t=q:w=…:g=…,equalizer=…,treble=…` (normalization then equalizer, a single `volume`, 0 dB filters omitted; libavfilter's `bass` / `treble` / `equalizer` with `t=q`, same RBJ biquads as AutoEQ). The chain contains commas: in `loadfile`'s `options`, it goes as `af=%<length>%<chain>` (unambiguous form of mpv's option lists); `file-local-options/af` takes the raw value. Changing the equalizer follows normalization (`refresh_filters`): chain replaced live on the current track (mpv rebuilds the filters, a micro-gap is possible), preloaded one removed then reloaded with its own. Verified with mpv 0.42 (`cargo test live_per_file_af -- --ignored --nocapture`): `af` = `volume` −12.20 dB (−6 + preamp −6.2), `bass`, `equalizer`, `treble` on the current track, `volume` alone on the preloaded one after the gapless switch, live change correct; `mpv -v` shows the graph built (`[bass] … float`). **Not yet verified with Ubuntu's mpv 0.37** (#316: the `%n%` form is old in mpv, but to be confirmed). On Android (0.5.82, #467): `EqAudioProcessor.kt`, see `docs/android.md`. **AutoEQ import**: `parse_autoeq` command (pasted text, or file read through `<input type=file>` on the UI side, without a dialog plugin), Equalizer APO's "ParametricEQ.txt" format: `Preamp:`, `Filter n: ON PK|PEQ|LSC|LS|HSC|HS Fc … Hz Gain … dB Q …`, `OFF` filters ignored, shelf without `Q` → 0.71, decimal comma accepted, 16 KiB at most. `PlayerState::equalizer` (name of the applied profile) → signal path: "EQ <profile>" under Decoding, verdict "Equalizer" (no longer bit-perfect, in exclusive mode too; mute stays the priority). Settings › Playback › Equalizer: `components/EqualizerSettings.svelte` (switch, profile, import, new profile, preamp, filter table, curve computed on the UI side for display only: `lib/eqCurve.ts`, tested). In the settings backup. Preview: `?route=settings&tab=playback&eq=1`.
- **Output device** (#79, `mpv/device.rs`, `player/output.rs`): setting `PlaybackSettings::audio_device` (`null` = system default, or `{id: "wasapi/{guid}", name}` validated on deserialization; prefixes `wasapi/`, `pipewire/`, `pulse/`, `alsa/` accepted everywhere, a choice from another platform simply ends up in fallback), passed as `--audio-device` at launch and set live through `set_property audio-device` (mpv reopens the output without interrupting the track). Verified with mpv 0.41 (`cargo test live_audio_devices -- --ignored --nocapture`, silence on the real output): `audio-device-list` is notified as soon as it is observed (`auto`, `wasapi/{guid}` + description, `openal`: only `wasapi/` entries are kept; on Linux mpv lists the outputs of all its drivers, PipeWire also appearing through `pulse/` and `alsa/`: `device::pick` only keeps the first driver among `pipewire/`, `pulse/`, `alsa/` present in the list); a device missing at load time makes the file fail (`end-file` `error`, `audio output initialization failed`), **mpv does not fall back on its own**. On plug / unplug, the list is notified again (`ao_hotplug_event` in `ao_wasapi_changenotify.c`, not testable without unplugging a device). The actor decides (`device::resolve`, tested): choice present → it, otherwise `auto` + toast, the setting staying intact; automatic return + toast when plugged back. Safety net: an `audio output initialization failed` error on a chosen device marks it unusable until the next list and restarts the track at the same position, without consuming the new URL attempt. `PlayerState::output_device` (`name`, `systemDefault`, `missing`): real name in `SignalPath` (Output node, in `--warn` during a fallback; only as a tooltip in Studio's compact bar). In `auto`, the name comes from the Windows default device (`IMMDeviceEnumerator::GetDefaultAudioEndpoint(eRender, eMultimedia)`, same role as mpv, guid from `GetId` found in the list). Settings › Playback › Audio output: `components/OutputDevicePicker.svelte` (`audio_devices` command, then `audio-devices` event), classes `.cache-sizes.audio-devices` / `.cache-size.audio-device` (themes already ready), unplugged choice shown as "unplugged". Preview: `?route=settings&tab=playback&device=dac|missing`.
- **Pause on unplug** (0.5.16, #348, `player/output.rs`): setting `PlaybackSettings::pause_on_unplug` (on by default, Settings › Playback › Audio output, desktop). `Output::set_list` (tested) compares each new `audio-device-list` with the previous one: if the device in use (the choice, or in `auto` the system's) is no longer there, it is "unplugged". During playback, the actor pauses **before** setting `audio-device` (nothing comes out of the speakers), with a single toast that replaces the fallback one; the fallback and the return on plugging back stay in place, without automatic resume. A change of the default device whose old one stays listed does not count; neither does the first list. On Linux, `system_default_id` returns nothing: only a chosen device is detected. **Not verified on real hardware** (like #79's hotplug); in exclusive mode, mpv can also report the output failure (`on_exclusive_failed`), hence two messages.
- **Per-output-device settings** (0.5.62, #416, `player/profiles.rs`, pure tested logic): setting `PlaybackSettings::device_profiles` (off by default, Settings › Playback › Audio output, desktop). Profile = volume (level + mute), normalization, exclusive mode and, since #428, the applied equalizer profile (`equalizer`, identifier or `null` = off; `#[serde(default)]` to reread profiles recorded before), stored under the identifier of the device **actually in use** (`Output::in_use`: the choice, or in `auto` the Windows default device; no separate profile for "default", so changing the default output in Windows changes the profile, and the fallback of an unplugged DAC takes the speakers' profile). Each change of volume, normalization or exclusive mode is recorded for the current device (`note_device_profile`); at the end of `apply_output_device`, `sync_device_profile` applies the new device's profile if it has one, otherwise it inherits the settings in force. Normalization, exclusive mode and equalizer (switch and chosen profile, not the profile list) living in `playback.settings`, they are saved there again and the `playback-settings` event makes Settings reread them. Turning the setting on records the values in force for the current output, without applying anything; turning it off keeps the profiles. In `SetPlaybackSettings`, normalization and exclusive mode are set before the device, so they are recorded on the old output. Stored in `kv` (`playback.deviceProfiles`, with the 2 s cadence), 32 at most (the least recently used forgotten), never exported. On Linux in `auto`, unknown device (`system_default_id` empty): nothing is recorded or applied. Key stability: `wasapi/{guid}` is the WASAPI endpoint ID, persistent for the same device; **not verified on real hardware** (like #79 and #348). Preview: `?route=settings&tab=playback&profiles=1`.
- A micro-gap on a sample rate change in exclusive mode is **expected** (device reopened). It is not a bug to fix.
- mpv resolution (`mpv::process::executable`): `SEAGLASS_MPV_PATH`, otherwise `mpv.exe` next to `seaglass.exe` (installed by the installer), otherwise, in debug only, the one in `PATH` (#261: in release, Windows would also search the current folder). Release build without bundled mpv or variable: `MpvError::Missing` and `MpvIssue::Missing` banner ("reinstall Seaglass", preview `?mpv=missing`).
- **CPU without AVX2** (#92, option 3 chosen by the user: keep the x86-64-v3 build): nothing is blocked in advance, mpv is launched normally. If it fails (launch, IPC connection, or `Disconnected`), `MpvIssue::diagnose` (`mpv/mod.rs`) gives `CpuUnsupported` if it is the installer's mpv (`process::is_bundled`) **and** `IsProcessorFeaturePresent(PF_AVX2_INSTRUCTIONS_AVAILABLE)` is false (`mpv/cpu.rs`, `Win32_System_Threading` feature), otherwise `Stopped`. No false positive with an mpv chosen by the user or if the bundled build changes. `PlayerState::mpv_issue` (in the state and not as a toast: the failure at launch comes before the webview listens) → persistent banner `components/MpvIssue.svelte` above the playback bar (`.mpv-issue`, `.mpv-issue-title`, `.mpv-issue-hint`), which recommends a classic x86-64 mpv through `SEAGLASS_MPV_PATH`; the toast of a requested playback reuses `MpvIssue::message`. Preview: `?mpv=cpu` or `?mpv=stopped`. Not testable on the dev and CI machines (they have AVX2).
- **Frozen or crashed mpv** (0.4.111, #255): each command has 5 s to answer (`COMMAND_TIMEOUT`, `MpvEngine::apply_within`); beyond that, `ProcessGuard::terminate` kills mpv and the pipe closing gives `Event::Stopped`. The actor (`player/recover.rs`) then restarts mpv with the same `Launch`, reapplies loop and volume and resumes the track at its position if it was playing (paused: loaded on the next Play). At most one restart every 5 min, none if `diagnose` says AVX2 is missing or mpv is missing, nor during shutdown or an update (`ProcessGuard::kill` sets `closing`, `Launch::may_restart`). Tests: `unresponsive_mpv_times_out`, `restarts_at_most_once_per_cooldown`, and with a real mpv `cargo test live_engine_terminate -- --ignored --nocapture`.
- mpv is attached to a Windows Job Object with `KILL_ON_JOB_CLOSE` (`mpv/job.rs`): it dies with the app, even on a crash. On Linux (#17), `process::die_with_parent` sets `prctl(PR_SET_PDEATHSIG, SIGKILL)` between `fork` and `exec` (`extern` declaration of `prctl`, no dependency). The signal follows the death of the **thread** that launched mpv: `spawn` must keep being called from an async task (tokio worker thread), never from `spawn_blocking`.

## Manifests and pipe

- **Manifests**: `mpv::serve` listens on `127.0.0.1:<random port>` and keeps the last 4 MPDs in memory; mpv receives `http://127.0.0.1:<port>/<token>/<track>-<n>.mpd`. The token (128 bits, hex, drawn when the server starts, #86) protects the signed stream URLs from the machine's other processes and accounts: without it, 404. Reading and writing under a 5 s timeout, 16 simultaneous connections at most (beyond that, closed at once); tests in `serve.rs`, including the timeout one (~5 s).
- **mpv pipe**: `\\.\pipe\seaglass-mpv-<pid>-<128 random bits>` (`process::pipe_id`, `OnceLock` drawn once per launch, shared by `spawn` and `ipc::connect`): a local process cannot create the pipe before mpv (#86).

## Queue, errors and persistence

- **Actor** split into `actor.rs` (loop, commands, emission), `playback.rs` (mpv window, gapless, errors) and `persist.rs`. Network resolutions (metadata + stream) run outside the actor and come back as `Cmd::Resolved`; the `load_req` / `preload_req` counters discard stale answers.
- **Previous** (`Player::previous`, choice in `previous_action`, tested): past 3 s (or with no history) back to the start of the track, otherwise the previous track; both **resume playback**, even from a pause (#47, the maintainer's choice): the restart sends `SetPaused(false)` after the seek, or loads the track at 0 when it is not in the engine (restored, ended). Next already plays. The history keeps the origin of each track (`queue/entry.rs`: `Context`, `Manual`, `Detached` = context replaced or queue cleared). Going back to a context track from a context track moves the cursor back ("Next" returns to the track left); otherwise the track left is put back at the head of the manual queue, in its place if it came from there, **recalled** otherwise: a new context discards recalled tracks and keeps the user's (#166: going back up a replaced context filled the manual queue for good, and those tracks came before any new list, shuffle included). Old format reread (`from_context`, identifiers only in `manual`).
- **Shuffle**: Fisher-Yates over all the other tracks of the context, current track first. `play_tracks` takes a tri-state `shuffle` (#526): `true` ("Shuffle" buttons) turns it on and starts on a random track, `false` ("Play" buttons of a page, the library, the recap, drive mode, the remote's album / playlist) turns it off, `null` (a track picked in a list, the command palette, the remote's single track) keeps the current mode.
- **Errors**: new URL once per track, then next track with a toast; stop after 3 consecutive failures. These two toasts carry a `kind` (`unplayable`, `stopped`) that the UI can dress depending on the theme (easter egg #399), the message staying the backend's.
- **End of queue** (0.5.53, #399): `PlayerState::ended` becomes true in `on_queue_end` when no automatic radio is on its way, or when the expected radio fails or adds nothing; reset to false by `load_current`. `idle` is not enough (also true at startup). `PlayerState::soundtrack` is recomputed in `emit` from `tidal/soundtracks.rs`, a short list of hand-picked albums (`models::Album` has neither genre nor "soundtrack" type); the user chose the list over a detection based on the title. To add an album: take its id from the album URL (`tidal.com/album/<id>`), check it answers on the catalog (album view in the app, or `live_catalog`), and add it to `SOUNDTRACKS` with the title as a comment; every edition (standard, deluxe, expanded) has its own id.
- **Persistence**: `seaglass.db` in `%APPDATA%\dev.seaglass.app\` (tables `kv` and `tracks`). Written at most every 2 s (position only during playback on Android: 10 s, #147): position only, or queue + metadata of referenced tracks missing from the table if the queue changed (incremental since #90, see "Backend performance" in `tidal.md`). **Shutdown** (#260, desktop): `RunEvent::Exit` and the updater's `on_before_exit` call `player::flush_blocking` before stopping mpv: `Cmd::Flush` writes everything pending (and the position) without waiting for the interval, after the previous write has finished (`Player::last_write`, otherwise an older write could land after it), and answers through a `std::sync::mpsc` channel awaited for 1 s at most (no `block_on`: the updater can call from a tokio context). At startup, the queue is restored paused and the track is only loaded into mpv on the first click on Play, at the saved position.
- **Metadata cache** in memory (`tidal::cache`), fed by search and lists; it lets the queue be displayed without a request. Bounded since #90 (queue tracks pinned).
- Verified in real playback: preload 25 s before the end (`playlist-count=2`), switch without reload then `playlist-count=1`, restore at the right position with mpv idle.
- Verified in real playback: `audio-codec-name=flac`, `current-ao=wasapi`, output `s16` 44.1 kHz for a 16/44.1 track.
- **Resume on launch** (0.5.16, #353, `player/persist.rs`): setting `PlaybackSettings::resume_on_launch` (off by default, Settings › Playback › Startup, desktop; Android out of scope: the system relaunches the media service on its own). `lib.rs` passes `may_resume` to `player::spawn`: false with `--minimized` (launch at sign-in, even without a notification area icon) or if the previous launch crashed (`logs::previous_launch_crashed`). The actor waits for `current_session()` in a task, then `Cmd::ResumeOnLaunch` loads the restored track at its position, unless something was already started (`load_req != 0`) or less than 5 s remain (`worth_resuming`, tested). Without a session, nothing. After an update, the app restarts like a normal launch: playback resumes too.
- **Restored state**: mpv's `pause` is ignored as long as no track is loaded (otherwise the initial `pause=false` clears the restored "paused" state); `paused=false` is set explicitly after a load.

## Queue commands

- **Batch add** (#15): `enqueue_tracks(trackIds, next)` adds to the manual queue in the given order ("Play next" = `push_front` starting from the last one, otherwise the album would be reversed). Buttons in the Album and Playlist headers (`PageHeader` `queueable`). Queue tests in `player/queue/tests.rs`.
- **Play from the queue** (0.4.66, #167): `play_from_queue(part: "manual" | "upcoming", index, trackId)` → `Queue::jump_to` (tested), index into `QueueView::manual` / `upcoming` as displayed; ignored if it is no longer `trackId` (queue changed since display). Manual queue: tracks before it are removed. Context continuation: cursor set on it in the current order (repeat All included), manual queue kept (it comes right after). Skipped tracks do not go into the history. Same gesture as the other lists in `QueueList` and the `.np-next` band (`onPlay` of `TrackRow`: double click or cover, tap on Android, "Play" in the menu); compact "Up next" list of "Now playing" as `.next-item` buttons (one click). Preview: `?nowplaying=1&manual=1`.
- **Clear the queue** (0.4.6, #41): `clear_queue` → `Queue::clear_upcoming` empties the manual queue and the context; the current track continues, detached from the context (nothing follows it, even in repeat All), the history stays. "Clear queue" button at the top of `QueueList`.
- **Undo a clear or a removal** (0.5.18, #349): before `ClearQueue` and `RemoveFromQueue`, the actor keeps a copy of the queue (`Player::undo_queue`, a single level). `mark_queue_dirty` forgets it: any other change to the queue, including moving to the next track, makes undoing impossible. `restore_queue` → `true` if the copy existed and the current track is the same (the whole queue is put back, then `on_queue_changed`), otherwise `false` and the UI says so. Removals by Jam guests (`RemoveFromQueueIds`) cannot be undone. No unit test: the rule lives in the actor, verified in the preview with the mock backend only.
- **Save as a playlist** (0.5.13, #327): "Save as playlist" button next to "Clear queue"; `queue_track_ids` asks the actor for `Queue::play_order` (current track, manual queue, context continuation, repeat All included, tested), capped at `MAX_ADD` (10,000) since the UI only receives 50 tracks of the continuation. Opens `PlaylistPicker` with these tracks: new or existing playlist, already verified batch add (`add_to_playlist`, duplicates ignored).
- **Reorder the queue** (#80): `move_in_queue(from, to)` → `Queue::move_manual` (the `from` entry ends at index `to`, tested). Only the manual queue can be reordered, the context keeps its order. The preloaded track always being `peek_next`, the actor only removes it from mpv if the move changes the head of the manual queue: reordering the middle does not break gapless. UI in `QueueList` (drag and drop shared with playlists since #201: `lib/reorder.svelte.ts`, `Reorder` class and `keyboardMove`): HTML5 drag and drop (insertion marker `.drop-before` / `.drop-after` in the accent, `.dragging` row faded, covers not draggable), Alt+↑ / Alt+↓ on a focused row (focus follows the row on the next `queue-state`), "Move up" / "Move down" in the context menu (`onMoveUp` / `onMoveDown` of `TrackRow`). No optimistic display. Preview: `?queue=1&manual=1` (four tracks in the manual queue). A drag event created by script must carry a `DataTransfer` and `clientY`.
- **Playing from** (0.4.49, #124, `player/source.rs`): `play_tracks(…, source)` carries a `PlaySource` tagged by `kind` (`album` id + title, `playlist` uuid + title, `mix`, `radio` seed + id + title, `artist` id + name, `likedTracks`, `search` query), cleaned by `sanitize` (non-empty label, 200 characters, uuid and mix id checked; invalid = ignored, playback is not refused). Details in [`jam.md`](jam.md#playback-handoff-414-0566-desktop--android).
- **One stream per account** (0.5.117, #35, `player/takeover.rs`; protocol in [`tidal.md`](tidal.md#one-stream-per-account-35-spike-verified-on-2026-11-25)):
  - **Claim**: `note_claim` marks the commands whose result is playing: `PlayTracks`, `PlayFromQueue`, `Next`, `Previous`, `SetPaused(false)`, `TogglePause` when it resumes, `ApplyHandoff`, `ResumeOnLaunch`, `AnswerHiresOffer(true)` (it reloads and resumes) and the start of a blind test. They come from the user, the media keys, Jam guests or the remote control. Resume on launch counts: otherwise this device and another would play together, silently.
  - **Not claims**: the player's own moves (gapless, next track at the end, error retry, automatic radio, engine recovery).
  - **Sending**: after each command or event, `sync_takeover` sends Pushkin a `Claim` (once audio plays, so a Play that fails pauses nobody), or `Playing` / `Stopped` when that changes. It never waits.
  - **Takeover**: `Cmd::PlaybackTaken` pauses and toasts, only while audio plays (`loaded && !paused`). Repeated notifications, and a handoff between two Seaglass devices (the one handing off is already paused), change nothing.
  - **Reload paths while paused**: the other reloads that resume (error retry, output fallback, radio, recovery) only run while playing.

## Volume, sleep timer, automatic radio

- **Volume** (#29, `player/volume.rs`): `set_volume` (0–100) / `set_muted` → mpv's `volume` / `mute`, also applied at startup. mpv applies a cubic gain: no curve on the app side, 100 = unity gain. Persisted in `kv` (`player.volume`) with the 2 s cadence, reread even without a queue. Moving the slider unmutes; unmuting at 0 starts again from 50. Volume ≠ 100 or muted → verdict "Software volume" / "Muted" in the signal path, never bit-perfect.
- **Sleep timer** (#85, `player/sleep.rs`): `set_sleep_timer(timer)` with `{kind: "minutes", minutes}` (1 to 600, the UI offers 15 / 30 / 45 / 60 / 90), `{kind: "endOfTrack"}` or `null` (cancels). Not persisted. Duration: deadline as an `Instant` (`Player::sleep_deadline`) checked by the actor's one-second tick, then pause (mpv stays running); `PlayerState::sleep` carries `endsAt` (ms epoch): the UI computes the countdown, without a `player-state` per second. End of track: on activation, the preloaded track is removed and `maybe_preload` suspended (otherwise the next would start gapless), `loop-file` lifted in repeat One; at the natural end (`on_end_file`), `sleep_after_track` advances the queue **without loading** the next track, paused, like a restored queue (Play loads it; in repeat One, same track from the start). Skipping to the next track by hand keeps the timer. End of queue (#436, `{kind: "endOfContext"}`): comes down to "End of track" as soon as `Queue::at_end()` (manual queue empty, cursor on the last track of the play order, shuffled or not; repeat All's return to the start and automatic radio do not count), or at once in repeat One (the track loops): `sleeps_at_end_of_track()` is evaluated on each call, so the last track is never followed gapless. Manual queue tracks are played before the pause. The UI names the target from `QueueView::source` (`sleepScope()`: album, playlist, otherwise queue). UI: `components/SleepTimer.svelte` (moon, shared `openMenu` menu, remaining time `.sleep-remaining`), in the playback bar and in "Now playing". Preview: `?sleep=30|track|context`.
- **Automatic radio** (#78, `player/radio.rs`): setting `PlaybackSettings::auto_radio` (Settings › Playback › End of queue), **off by default** (the end of an album stopping playback stays the base behavior). Requested at preload time (`maybe_preload` without `peek_next`), if `Queue::wants_radio` (current track, nothing after, repeat Off: All and One take priority): `tidal.radio(Track, current)` outside the actor → `Cmd::RadioResolved` (`req` counter, a single request per track as long as the queue does not change: `mark_queue_dirty` clears `asked`). `Queue::extend_with_radio` (tested) refuses if the current track changed or a next one appeared; discards the current track, the last 100 of the history and duplicates; new context = current track then the radio, cursor on it ("Previous" stays consistent). The first track is preloaded at once: gapless kept. Track finished before the answer (`on_queue_end`): playback restarts when it arrives. `Queue::radio` (seed, persisted, `#[serde(default)]`) is cleared by a new context or "Clear queue"; `QueueView::radio` → in `QueueList`, "Next" becomes "Radio of <title>" (`.queue-radio`). Preview: `?queue=1&autoradio=1`.

## Blind test (0.5.70, #434)

Solo for now; multiplayer through the Jam will come next, on the same logic.

- **Game** (`player/blind/game.rs`, pure tested logic): rounds drawn without replacement from the tracks sent by the UI that are in the catalog cache (every page offering the button puts its tracks there), content filter applied, duplicates removed; at least 4 tracks with different names (`MIN_POOL`), at most 50 rounds. 15 s clip (`CLIP_LENGTH`) drawn between 20 % of the track (60 s at most) and 10 s before the clip's end; track too short: in the middle. Points: title 2, artist 1 (`ROUND_POINTS` = 3 per round); in "4 choices" mode (three other tracks from the pool, with different names), the right one is worth 3. Streak = consecutive rounds with at least one point. Unplayable track (`on_track_failed`): another from the pool replaces it without counting a round; three failures in a row stop the game and give the queue back.
- **Free answers** (`player/blind/answer.rs`, tested): lowercase, Latin accents folded by hand (no Unicode crate in the dependencies), punctuation and apostrophes removed, "&" and "et" = "and"; the title loses what `foreign::strip_decorations` removes (parentheses, "feat.", version suffix), the artist a leading "The"; any of the track's artists counts. Typos tolerated (Levenshtein): none under 4 characters, 1 up to 6, 2 up to 12, 3 beyond. The same input can name both: the artist is searched first in a window of words (one word more or less), removed, then the title in the rest ("daft punk" does not find the title "Punk"); the whole input close to both counts twice (self-titled track).
- **Actor** (`player/blind/mod.rs`): `Cmd::BlindTest(BlindCmd)` (`Start`, `Answer`, `Replay`, `Next`, `Quit`, `Get`); `blind-test` event (`BlindTestView`, or `null` after the game) emitted by `emit` when `blind_dirty`. The previous queue is **set aside** (`BlindTest::saved` and its position): each round replaces `Player::queue` with a single-track queue loaded at `clip_start`. `main_queue()` serves `queue-state`, saving (`write` also takes the previous position from it: closing mid-game gives the queue back at launch), shuffle / repeat and manual queue commands ("Play next" during the game goes into the queue for afterwards). Starting a context, a queue track or a handoff ends the game first (`blind_route`); Next = skip then next round, Previous = replay, Play on a finished clip = replay. At the end (`end_blind_test`): `stop`, resolutions in flight ignored (`load_req`), queue given back **paused, not loaded**, as at app launch.
- **Masking**: as long as the round is in `Guess`, `public_state` removes `track`, the hi-res offer and the soundtrack easter egg from everything that leaves the actor: `player-state`, `GetState` (Jam, remote, linked device) and observers (SMTC, MPRIS, Discord, notification area, Android notification). `PlayerState::blind_test` tells the UI a game is in progress. Once revealed, the round resumes the track where the clip stopped, until the next one.
- **Multiplayer** (0.5.71, #441, `player/blind/players.rs` tested, `jam.rs`): `Party { jam, host_plays }` chosen at start (`blind_test_start(…, jam, hostPlays)`, refused without a running Jam). Players = the host (`HOST_KEY`, id 0, if playing) and the guests who answer (Jam key: browser token or address, never shown), 32 at most, Jam first name. One answer per player per round; the round is revealed when all known players have answered, through "Reveal" (`BlindCmd::Reveal`, Next in multiplayer), or 20 s after the clip ends (`REVEAL_AFTER`, scheduled once per round, checked by the one-second tick; `revealAt` in ms for countdowns). Solo points, plus 1 for the first who found the title (order of arrival of answers). A player without an answer loses their streak. `BlindTestView` carries `party`, `players` (ranking, `answered`) and, for each round, `RoundResult::players`. A guest's answer: `BlindCmd::GuestAnswer` with the round number, refused if it is no longer the current round.
- **During the game**: no preload (`maybe_preload`), no automatic radio or "The End" card (`on_queue_end`), no hi-res offer, no listen in the history (`note_listen`). The clip pauses after 15 s (`blind_on_position`, `paused` set at once so as not to request the pause again on every position).
- **Clip started** (#445): `loading` drops as soon as the URL is resolved, before the engine plays; the page's ring then started too early and went back to the start. The game therefore keeps its own `Clip` state: `Waiting` on each round (and on reloading a replay), `Opened` on `Event::Loaded`, `Playing` at the first position strictly past the clip's start. Arming on `Loaded` discards a stale position from the previous round's track. `BlindTestView::clip_playing` comes from it, emitted once per round.

## Hi-res edition (0.4.8, #18)

- **Principle**: a track without the `HIRES_LOSSLESS` tag often exists in 24-bit on another edition (original album, reissue, compilation) with the same ISRC. `Track::isrc` (missing from tracks saved before 0.4.8: requested again through `tracks/{id}`), then `GET v1/tracks?isrc=<ISRC>&limit=50` (verified on 2026-10-30: all editions with their tags, ~130 ms; `cargo test live_hires -- --ignored --nocapture`). Dolby Atmos versions have another ISRC.
- **Twin album** (0.4.13, #55, `tidal/twin.rs`, pure tested logic): some labels publish the hi-res master as a separate album, with the same title, **under other ISRCs** (Eagles, "Hotel California (2013 Remaster)": `20767338` in 16/44.1 and `68709104` in 24/192, ISRC `USEE11300353` / `USEE11300195`). Neither `tracks?isrc=` nor search (which deduplicates editions) sees it; the artist's discography (`artists/{id}/albums`, with and without `filter=EPSANDSINGLES`) lists both. Fallback when the ISRC gives nothing: hi-res albums of the main artist with an identical title (case and spaces ignored), then a track with the same name, same version, duration within ±2 s. Discography loaded **in parallel** with the ISRC request; cache per artist (hi-res albums) and per twin album (hi-res tracks). Measured (`cargo test live_hires_twin -- --ignored --nocapture`): ~430 ms on the first track, ~170 ms for the album's following ones.
- **Choice** (`tidal/hires.rs`, pure tested logic): hi-res, playable (`streamReady` / `allowStreaming`), duration within ±2 s; preference for an album with the same title then the same explicit marking, otherwise the API's order. Result cached in memory by original id, "none" included; errors are not cached.
- **Resolution** (`player/upgrade.rs`): next track = search then stream during preload (invisible); current track = search in parallel with the original stream, limited to 1.5 s, without requesting the original stream if the answer is cached. The other stream is only kept if it is `HI_RES_LOSSLESS` and better (depth or rate, without losing on the other axis); otherwise, or on error, original stream. Measured: ~480 ms on first launch, ~250 ms afterwards (as much as a normal track).
- **What changes**: only the stream. Queue, history, favorites, SMTC and display keep the original track. `StreamFormat::hires_edition` (`EditionAlbum`: id and title of the edition's album being played, 0.4.110) → "Hi-Res · other edition" under the signal path's source, and (0.4.10) a line "Hi-res edition: <album>" under the full signal path (`.hires-edition`, "Now playing"; not in the compact version of the Studio bar, which keeps the tooltip). (0.4.110, #111) In "Now playing", under the album and above "Playing from", a line "Sound from the <album> edition · FLAC 24/192" (`.played-from.played-edition`, `.played-edition-format`), the name opens the edition's album. Really replacing the track was ruled out with the user: likes, playlists, queue and history must keep the chosen id. The UI infers nothing: everything comes from `player-state`. Choices confirmed by the user in the issue: visible indication, setting on by default. Preview: `?hiresedition=Thriller` (the mock backend also replaces a non-hi-res track played if the setting is on).
- **Setting** `PlaybackSettings::hires_upgrade` (Settings › Playback › Quality): `auto` (default), `ask` or `off` since 0.4.15 (#59); the old boolean is reread (`true` = `auto`). Applied to the next resolution (`Cmd::SetPlaybackSettings`, which replaces `SetCacheSize`). The other edition's master may differ (another remaster): that is the reason for the indication and the setting.
- **"Ask" mode** (0.4.15, #59, `player/upgrade.rs`): the original track starts without waiting for the search; `maybe_offer_hires` then runs it in the background (`find_offer`: edition + `playback_format`, without reading the stream) and, if the edition is better (`is_better`), `PlayerState::hires_offer` carries its format (album in `hires_edition`). `offer_req` counter against stale answers; offer removed on every track or setting change. Banner `components/HiresOffer.svelte` above the playback bar; `answer_hires_offer(accept)`: the answer applies to the album for the session (`Player::hires_answers`, not persisted). Yes = reload at the same position (playback resumes, the preloaded next track is removed), then automatic switch for the album's other tracks; no = no more offer for this album. Track info: `played` only in automatic mode. Not a modal dialog: it would interrupt listening on every track of an album.
- **Link to the hi-res album** (0.4.15, #59): `hires_twin_album(albumId)` (`tidal/twin.rs`) = hi-res album of the main artist with the same title (twin album logic, discography cached), `None` if the album is already hi-res. Called by `Album.svelte` after display; "Other versions" from `pages/album` (#350) does not always give it (see `docs/tidal.md`), this twin is removed from that row; banner "This album exists in Hi-Res → Open" (`.hires-twin`). Measured: ~500 ms on the first call (`cargo test live_hires_twin_album -- --ignored --nocapture`). Preview: `?hiresoffer=<album>` (Ask mode, banner) and `?hirestwin=1` (album page).
- Verified in real playback (`cargo test live_hires_playback -- --ignored --nocapture`): *Billie Jean* from "Thriller 25 Super Deluxe Edition" (1632061, 16/44.1 only) → hi-res edition 97320484, mpv decodes FLAC `s32` at 96 kHz.
- Classes overridable by themes: `.hires-edition`, `.hires-edition-album` (Acidwave: mono in capitals; Surrealism: italic), `.hires-offer`, `.hires-offer-title`, `.hires-offer-album`, `.hires-offer-accept`, `.hires-offer-dismiss`, `.hires-twin`, `.hires-twin-text`, `.hires-twin-open` (0.4.15); the setting reuses `.cache-sizes` / `.cache-size` (with `.hires-modes` / `.hires-mode`).
