# Interface

Seaglass implementation notes, read on demand (index in [`CLAUDE.md`](../CLAUDE.md)). The UI has no business logic: it displays the state received from the backend and sends commands.

## Navigation, settings and preview

- **UI**: navigation through a route stack (`lib/stores/nav.svelte.ts`) without URLs, Back button in the header. Playing a track from a list puts the whole list in context; "Shuffle" goes through `play_tracks(…, shuffle: true)`, the backend picks the starting track.
- **UI settings**: `ui_settings` / `set_ui_settings`, JSON in `kv` (`ui.settings`). Unknown theme refused on deserialization.
- **Settings backup** (0.5.34, #352, `commands/settings/backup.rs`, tested): `export_settings` returns `{format: "seaglass-settings", version: 1, ui, playback}` (without `audioDevice` or `exclusive`, specific to the machine; no token, queue, history or searches). `import_settings(text)` (256 KiB at most, format and version checked) sets the keys **one by one** on the current settings: each attempt goes through the deserialization of `UiSettings` / `PlaybackSettings` again (theme, zoom, accents…), plus `pins::normalize`, `sorts::are_valid` and bounds on the home layout. Key refused, unknown or specific to the other platform (desktop: `closeAction`, `discord`, `zoom`, `cacheSize`, `pauseOnUnplug`, `resumeOnLaunch`; Android: `wifiQuality`, `cellularQuality`, `lowBatteryQuality`): ignored and returned in `ImportReport` (`ui.theme`, `playback.autoRadio`…). Saved through `store_and_apply` (like `set_ui_settings`), pins resynced, playback settings sent to the player if they change. No `tauri-plugin-dialog`: copy through `copyText`, import through a text area (Settings › Application), then `location.reload()` to reread everything from the backend.
- **Library export** (0.5.55, #330, `export.rs` tested, `commands/export.rs`, desktop only): `export_library` reads liked tracks, albums, artists and playlists (the user's and followed ones, one by one: `TidalClient::playlist_tracks`, which reuses the kept copy if it exists but replaces none, otherwise 200 playlists would empty the cache of the last 20), then writes `Documents/Seaglass/export-YYYY-MM-DD-hhmmss/` (UTC time, no date crate: `utc.rs`) and opens the folder (`opener`). Content: `library.json` (`format: 1`, `truncated` per list, ISRC, added dates in ISO 8601) and RFC 4180 CSVs with BOM (Excel reads them as ANSI otherwise), artists separated by `; `; one `playlist-NNN-<title>.csv` per playlist (number: duplicate titles, order kept; title cleaned for Windows, 60 characters). Explicit content filter not applied (it is a backup). `library-export` event (`{done, total}`) after each playlist, `cancel_library_export` stops before the next one; one export at a time. Unreadable playlist: left out, title returned in `failed`. No `tauri-plugin-dialog` (no choice of location). Android: not offered (the app's Documents folder is not visible); it would need a file share. UI: `lib/stores/libraryExport.svelte.ts`, Settings › Application. Preview: simulated progress over 3 playlists (asynchronous handlers accepted by the mock).
- **Content filter** (0.5.28, #368; AI in 0.5.29, #369, `src-tauri/src/content.rs`): `UiSettings::content` (`hideExplicit`, off by default; `hideAi`, **on** by default, `Default` written by hand so that settings from before 0.5.29 get it too), global copies (`AtomicBool`, initial values = `Default`) set by `apply_to_backend` at startup and on every `set_ui_settings`. The `Filtered` trait removes what is hidden from **what the service offers**, at the output of the commands: `search`, `album` (the album stays, its hidden tracks go), `album_related`, `artist`, `artist_extra`, `playlist` / `cached_playlist` (except `mine`), `mix`, `radio`, `home` / `home_rest` (a row emptied by the filter disappears, "Played in Seaglass" included), `feed`, `hires_twin_album`, Jam search / links / albums, automatic radio (`player/radio.rs`). **Never** favorites or your own playlists: chosen by the user, and their changes go through track positions (a filter would shift "Remove from playlist"). The playlist copy (`snapshots`) is saved before the filter. Pages already shown are not reloaded: the setting applies to lists loaded afterwards. Settings › Playback, "Content" group; preview `?explicit=hide` (the mock backend does not filter). "E" and "IA" / "AI" badges (`.badge.muted`, `t.common.ai`) on track rows, album cards and the album header; preview `?ai=show` for the AI switch.
- **Album color**: `vibrantColor` → `AlbumRef::color` / `AlbumSummary::color`, filtered to `#rrggbb` (it goes into the CSS). The UI sets it as `--album` on `<html>`.
- **Signal path** (`SignalPath.svelte`): source → mpv → output, verdict "Bit-perfect" (exclusive only) / "Native rate" / "Resampled" / "Reduced depth" / "Compressed". The Output node and the verdict read `deviceFormat` (`audio-out-params`, format actually written to the output), otherwise `output` (Android). In shared mode, it is the Windows mix format (often 48 kHz float: a 44.1 kHz stream is "Resampled" there, which is accurate); "Native rate" is never presented as bit-perfect there. Preview: `?exclusive=1` (exclusive mode, `deviceFormat` = stream format; otherwise fake 48 kHz float).
- **Shortcuts**: Space (play/pause), Ctrl+K (command palette, desktop; Search page on Android), `/` (Search page), Esc (close), Alt+← (back), Ctrl+, (settings), Ctrl+↑ / Ctrl+↓ (volume ±5), F11 (full screen, desktop), global shortcuts chosen by the user (#413, see `system.md`), Ctrl+M (mini player, desktop, #384), Ctrl + "+" / "-" / 0 (interface size, desktop). **Interface size** (0.5.11, #337, `commands/settings/zoom.rs`): `UiSettings::zoom` (80, 90, 100, 110, 125, 150, any other value refused) applied through `WebviewWindow::set_zoom` at startup and on every `set_ui_settings`, rather than a CSS variable on `font-size` (themes use `px`). Desktop only: Android has the system display size. Settings › Appearance; shortcuts in `App.svelte` (`stepZoom`). **Full screen** (0.4.51, #131, `commands/window.rs`, desktop only): `set_fullscreen(bool)` on the `main` window returns the state read back; `fullscreen` event emitted on `WindowEvent::Resized` when the state changes, `fullscreen` command for the initial state (`lib/stores/window.svelte.ts`). Independent of "Now playing" (the issue's choice), which has a `.fullscreen-toggle` button next to Close. Esc first leaves full screen, then closes "Now playing". Nothing on Android. **Full-screen lag on Windows** (0.5.59, #191): a borderless window that covers the screen exactly is switched by DWM to "independent flip" after ~2 s when it has focus, and WebView2 gets one frame of lag there (hover lagging behind the cursor, whatever the theme, not in a maximized window). The "Disable fullscreen optimizations" box on `Seaglass.exe` does nothing (display goes through the WebView2 process). After native full screen, `overflow` therefore enlarges the window by one pixel toward an edge with no neighboring screen (bottom, top, right, left; `overflowed`, tested): it still covers the screen (taskbar hidden) without matching it. tao only realigns it if it changes screen; leaving restores the original placement. The overflow goes through `SetWindowPos` directly: tao's `set_position` / `set_size` clear its "maximized" flag, and leaving then went through the restored window before maximizing.
- **Command palette** (0.5.60, #412, desktop only): `components/CommandPalette.svelte`, opened by Ctrl+K or the header's "Search" button (`stores/palette.svelte.ts`). **Single registry** of actions in `lib/actions.ts` (`ACTIONS`: id, group, translated label, keywords, shortcut shown, `available` condition, `run`): the palette shows those offered, and `App.svelte` runs its shortcuts through `runAction(id)` (settings, mini player, full screen, size, volume, back, search); only key recognition stays in `onKeydown`. Space calls `togglePause` directly (without a loaded track, the command is sent anyway). What only `App` knows how to do ("Now playing", queue, session) goes through `setActionContext`. Ranking in `lib/palette.ts` (tested): case, accents and word order ignored, start of a word of the label > start of a keyword > middle of the label, label that starts with the query first. Without a query: all actions, by group; with a query: 8 actions at most, then content through the `search` command (300 ms after the last keystroke, 2 characters at least, stale answers discarded), 3 results per type. Enter on a track plays it (source `search`), on an album, artist or playlist opens its page. Exclusive mode toggled from the palette increments `playbackSettingsChanged`: the Settings page rereads its playback settings, otherwise it would write back the old value on the next change. Classes: `.command-palette`, `.palette-input`, `.palette-row` (`.active`), `.palette-section`, dialog colors (`--dialog-*`), so readable in every theme without an override. Preview: `?palette=1`.
- **Generated IPC types** (#44): `ts-rs` 12, **dev-dependency only** (`#[cfg_attr(test, derive(ts_rs::TS), ts(export, export_to = "../../src/lib/bindings/"))]`): nothing reaches the app, and each type gets an `export_bindings_*` test that writes `src/lib/bindings/<Type>.ts` (path relative to ts-rs' default `src-tauri/bindings/`). `ipc.ts` re-exports them in place of its hand-written copies; the files are committed, ignored by Prettier, and CI (`linux`, "Generated bindings") fails if `cargo test` changed them. `u64` and `i64` become `bigint` by default: identifiers and ms timestamps carry `#[cfg_attr(test, ts(type = "number"))]`. Doc comments become JSDoc, hence in English. `no-serde-warnings`: `transparent` and `from` are not read by ts-rs (a newtype still gives its inner type). Chosen over `tauri-specta` (still `2.0.0-rc` in 2026-11, and its generated `invoke` calls would bypass `transport.ts` and the mock backend). Moved so far: `PlayerState` and its types (step 1). Moving one showed real drift: the hand-written `Track.isrc` and `AlbumRef.coverSmallUrl` / `coverLargeUrl` were optional where Rust always sends them. Next groups: `QueueView`, settings, pages. To move one: derive on the Rust types (and those they contain), `cargo test export_bindings`, replace the copy in `ipc.ts` with a re-export, fix what `pnpm check` reports.
- **Preview without Tauri**: `pnpm dev` then `http://127.0.0.1:1420/?theme=studio&route=album&nowplaying=1` (parameters: `theme`, `route` including `settings`, `mix`, `radio`, `contributor` and `smart` (with `list=topMonth|onRepeat|forgotten|neverPlayed`), `tab` (library tab or settings section `appearance|playback|app`), `nowplaying`, `queue`, `paused`, `loggedout`, `authfail` (session not resumed, automatic retry), `browserLogin=1` (sign-in through the system browser, as on Linux), `update`, `autostart`, `volume=60|muted`, `accent=ff5c8a`, `favorites=alloy,terminal` (favorite themes, #390), `lyrics=1|plain|none`, `trackinfo=1`, `truncated=1|nototal`, `hiresedition=<album>`, `hiresoffer=<album>`, `hirestwin=1`, `lang=fr|en`, `autoradio=1`, `mpv=cpu|stopped`, `manual=1`, `long=<n>` (playlist and liked tracks of n synthetic tracks), `platform=android` (touch layout), `ticks=1` (`player-state` at 4 Hz, `playbackTick()` exported for a measurement), `sleep=30|track|context`, `device=dac|missing`, `normalization=track|album`, `fullscreen=1`, `palette=1`, `slow=<ms>` (slowed playlist opening)). Several servers in parallel: `pnpm vite --port <n> --strictPort`. Svelte 5 delegates `change` and `input`: an event created by script must have `bubbles: true`. Data from `src/lib/mock/fixtures.json`, generated by `cargo test dump_ui_fixtures -- --ignored` (gitignored: contains the account's library). The mock branch is removed from the production build (`import.meta.env.DEV`). Without `fixtures.json`, or with `?demo=1`, the mock uses the invented catalog of `src/lib/mock/demo.ts` (#28).
- **Website demo** (#28, "Try it in your browser", `/try/`): the same UI and mock backend, built with `vite build --mode demo` (publishing: "Website" in [`release.md`](release.md)). `vite.config.ts` defines `__DEMO__` (true only in that mode): with `import.meta.env.DEV`, it keeps the mock in `transport.ts` and `App.svelte` (`initialView`, so the URL parameters above work there too) and mounts `DemoBanner.svelte` ("Demo · Invented catalog, no sound · Download Seaglass", bottom right above the player bar). The app's production build has neither (checked: no mock string in `dist/`). **Catalog**: `mock/demo.ts`, invented artists, albums, playlists and mixes (English names, nothing from TIDAL or an account, so it can be public), with a page per identifier (`Fixtures.pages`: album, artist, playlist and mix handlers look the id up) and a search over it (`searchDemo`); covers are the SVGs of `mock/demo/`, imported as `?url` so they are emitted only with the mock, and never inlined as `data:` (`assetsInlineLimit: 0` in demo mode). **Fixtures kept out**: in demo mode, a Vite plugin resolves `fixtures.json` to a virtual `export default null` (the real file is never read, not even by the JSON plugin, which `load` alone did not bypass); the publish script also fails on `resources.tidal.com` in the output. **Behavior**: `playbackTick` runs at 4 Hz from the start and the queue moves on at the end of a track (`demoTrackEnd`: Repeat One, manual queue, context, Repeat All, else paused); the appearance (theme, accents, favorite themes, language, motion, zoom) is kept in `localStorage` (`seaglass-demo-ui`) after each command, a URL parameter still wins; "Source code", "Report a bug" and the website open in a new tab; the search history is invented; under 700 px wide (without `?platform=`) the mock reports `android`, so a phone gets the touch layout, banner raised above the mini player. Nothing plays: there is no stream in a browser, and the site never talks to TIDAL.
- **Vite pitfall**: twice, after files were edited by script, a component's CSS stayed stale while its JS was up to date (rules missing from `?svelte&type=style`). Restarting `pnpm tauri dev` and emptying `node_modules/.vite` fixes it. The built-in browser pane, when hidden, also freezes animations and lazy image loading: for a capture, inject `*{animation:none!important}`.
- **README screenshots** (#507): `node scripts/screenshots.mjs` with the preview running on port 1420 rewrites `docs/images/*.webp` (headless Edge over the DevTools protocol, no dependency; another Edge path through `SEAGLASS_EDGE`). Covers come from the image CDN: the script reloads a page whose visible images failed and stops after three tries. Retake them when a theme or a shown view changes noticeably.
- **Frontend tests** (#264, `pnpm test`, also in CI after `pnpm check`): `vitest` reuses `vite.config.ts` (`test` block), so the Svelte plugin compiles `.svelte.ts` files and `i18n` / `platform` are imported as is. `node` environment, without a simulated DOM: events are partial objects, `swipe.test.ts` has a fake row (`EventTarget` + `classList` / `style`). Tests next to the module (`src/lib/<module>.test.ts`), data in `src/lib/testing/`; both are outside the bundle and ignored by the version check. Changing language: `i18n.lang = "en"`, reset to `fr` in `afterEach` (same for `platform.mobile`). Backend and navigation simulated through `vi.mock` (`links.test.ts`). Covered: `trackOrder`, `format`, `playSource`, `links`, `reorder`, `swipe`, `touch-reorder` (browser globals replaced through `vi.stubGlobal`, `requestAnimationFrame` played by hand). ## Pages and lists

- **Settings page** (#9, `views/Settings.svelte`): `settings` route, Appearance / Playback / Application sections. Since #45, `Settings.svelte` keeps the tab bar and the loading effects; the groups live in `views/settings/` (`Appearance`, `PlaybackOutput`, `PlaybackListening`, `AppSystem`, `AppData`, `AppAbout`), rendered with no wrapper element (the DOM stays `section.settings > div.group`, which themes rely on). The state they share (playback settings, update check, settings import, open changelog) is a `SettingsState` (`settings/state.svelte.ts`) created once per Settings mount: switching tabs resets nothing. Each component carries a copy of the scoped styles it uses (`.group`, `.setting-row`, `.setting-switch`, `.cache-size`, `.update-check`…): a global `.settings …` stylesheet would leak into nested components that reuse these class names and change specificity against `src/themes/*.css`. Strings: `i18n/settings.ts` spreads `i18n/settings/` (`themes`, `playback`, `app`), so `t.settings.*` stays flat. Entry points: sidebar, header button, `Ctrl+,`. Reachable when signed out (Back returns to sign-in). No more Appearance / About boxes: the Appearance section (`CurrentTheme.svelte`, `ThemePicker.svelte`, see `docs/themes.md`) and the Application section replace them.
- **Project links** (0.4.71, #188, `commands/project.rs`): "Source code" and "Report a bug or suggest an idea" under About (`.project-links`, `.update-check` buttons). Command `open_project_page(page: repo | newIssue)`, fixed URLs on the Rust side, opened through `tauri-plugin-opener` (registered after the single instance, no permission on the UI side). The repository is public; opening an issue requires an account.
- **Client identifier notice** (0.5.112, #38): published builds carry the PKCE client identifier of TIDAL's Android app (`.env`, built in by `build.rs`), which TIDAL does not authorize for other apps. The sign-in screen (`.client-notice`, under the disclaimer, "Learn more" link) and Settings › About (paragraph under the disclaimer, "Learn more" button in `.project-links`) say so; the link is `ProjectPage::ClientId`, the README section "TIDAL client identifiers".
- **Queue in "Now playing"** (#20): `components/QueueList.svelte`, shared with the Queue view. Panel collapsed by default, session state `ui.nowPlayingQueue`. Any navigation closes the "Now playing" view.
- **Customizable home** (#21, #22): `commands/settings/home_layout.rs` (pure logic, tested), setting `UiSettings::home { order, hidden }`, commands `set_home_layout` (sections in screen order; those missing from the feed keep their place) and `reset_home_layout`. `home` returns `HomeSection`s (with `hidden`): the UI hides outside "Customize" mode. Hiding applies to the section type. Reordering: Move up / Move down (keyboard, Android) and, on desktop, drag and drop of a row (0.4.106, #246, `Reorder` from `lib/reorder.svelte.ts` like the queue, `.drop-before` / `.drop-after` marker). On Windows, HTML5 drag requires `"dragDropEnabled": false` on the window (`tauri.conf.json`): otherwise Tauri captures drag and drop for file drops and WebView2 no longer delivers `dragover` / `drop` (#290, also applied to the queue and playlists). On Android, HTML5 drag does not work with a finger: long press (350 ms without moving more than 10 px) then drag, through the `touchReorder` action of `lib/touch-reorder.ts` (#290); the row follows the finger (`.touch-dragging`, `--drag-y`), `touchmove` is cancelled after the grab so the page does not scroll, and it scrolls on its own near the edges. Pitfall (#302): the grabbed row's `transform` enlarges the scrollable area, so auto-scroll went down endlessly below the list; the row is bounded to the list (from the first to the last row) and scrolling stops when the end of the list is `EDGE` px from the edge. The same `Reorder` places the marker and applies the move (`commit`). **Queue** (#450): long press there already opens the track menu, so `touchReorder` takes a handle there (`handle` option, `.queue-handle` on the right of the row, Android only): pressing it grabs the row at once, without waiting, and `touch-action: none` prevents the page from scrolling under the finger. **Featured** (0.4.71, #185): the album comes from all albums of the displayed sections (deduplicated), drawn at random once per launch (`featuredIndex`, module `$state` of `Home.svelte`); "Skip" button (`.hero-skip`, next to the `.hero` button in `.hero-wrap`, on hover on desktop, always on Android); can be hidden through the "Featured" row at the top of the editor (`HomeLayout::featured_hidden`, `set_home_featured` command, reset by `reset_home_layout`). The albums played most in the app come first in the draw (#202, see "Listening history" in `player.md`).
- **Contributor page** (0.5.83, #429, `views/Contributor.svelte`, endpoint in `tidal.md`): `contributor` route (artist id), opened by a name in the credits (Track info `.credit-artist`, album Credits) and by the "Credits" link of the artist page (`.artist-credits`, in the `meta` of `PageHeader`). A credit opens this page rather than the artist page: that is what you are looking for when clicking "Producer", and the header links to the artist page (`.contributor-artist`). Header (photo, "Credits", announced track count), `TrackList` with roles translated by `creditRole` under each track (`notes`), `.contributor-more` button "More tracks" (200 more, `nextOffset` from the backend) as long as some remain. Play / Shuffle and the context cover the loaded tracks; source `{kind: "contributor", id, name}` ("Credits of X" in "Playing from"). Preview: `?route=contributor` (batches of 8).
- **Liked tracks** (0.4.62, #161): Play / Shuffle buttons above the filter (`Library.svelte`, `.liked-header`), in a `header .info .actions` so themes dress them like those of `PageHeader`; they follow the sort, not the filter; hidden while searching in the list (#151). On Android, playlists and mixes without numbers (#162); albums and an artist's top tracks keep them.
- **List filter and sort** (#1, #2, `lib/trackOrder.ts`, `components/TrackTools.svelte`): presentation over an already loaded list, in Playlist and Library › Tracks. Playing a track from a sorted list puts the list in context in the displayed order; from a filtered list, the whole sorted list, starting at the clicked track (0.5.95, #496: the filter is for finding a track, as on Spotify; `playContext` and the `context` prop of `TrackList`, active shuffle shuffles the rest around it on the `set_context` side); Play / Shuffle in the header follow the sort but not the filter. `TrackList` accepts `positions` to keep the original numbers. Filter not remembered; sort remembered per list since 0.4.37 (#93): `UiSettings::sorts` (`{list, key, descending}`, `list` = uuid or `likedTracks`), pure logic in `commands/settings/sorts.rs` (tested: most recent first, 200 lists at most, the list's default sort removes the entry), command `set_list_sort(list, sort | null)` which returns the saved list; the UI reads the sort on opening (`listSort`) and saves it on every change (`saveListSort`, function bindings on `TrackTools`).
- **Pins** (0.4.6, #10, `commands/settings/pins.rs`, pure tested logic): `UiSettings::pins`, ordered list of `Pin` (`kind: playlist` with uuid + title, `mix` with id + title (0.4.118, #193), `likedTracks`, or `later` for the "Save for later" tab, 0.4.103, #244). On Android, pins are the driving mode tiles (`docs/android.md`). A pin's label and page: `lib/pins.ts`; key: `pinKey` (`stores/ui.svelte.ts`). `set_pins` validates (uuid `8-4-4-4-12`, duplicates removed, 50 maximum) and returns the saved list. `PinButton` in the Playlist and Mix headers (not radios) and in Library › Tracks; "Pinned" section under Library in `Sidebar`. The kept title is refreshed when the playlist is opened. Mock backend: arguments are Svelte proxies, a handler that returns them must copy them through JSON (`structuredClone` refuses them).
- **Pasted links** (0.4.75, #203, `commands/link.rs`, tested): command `open_link(text)` → `LinkTarget` (`album` with optional `track`, `artist`, `playlist`, `mix`) or `null`. Recognizes `tidal.com/browse/<type>/<id>`, `tidal.com/<type>/<id>`, `www.` and `listen.tidal.com`, with or without a scheme, `/u`, parameters, in the middle of a share text (2,000 characters at most); last valid pair of the path (`album/1/track/2` = the track). Only the type and a validated identifier (numeric, uuid, mix id) come out. A track is resolved to its album (`tidal.track`): the page opens with the track marked and centered (`Route` `album` + `track`, `TrackList` `highlight`, `.row.highlighted`). UI (`lib/links.ts`): Ctrl+V outside a field (window `onpaste`, signed in only), paste into the search, or Enter on a link in the search. **Android "Share" menu** (0.4.78, #203, not yet verified on the S21): the plugin's `ShareActivity` (`ACTION_SEND` `text/plain` filter, exported, without UI like `NowPlayingActivity`) passes the text to `Playback.share`, kept in `pendingShare` until Rust has connected the session (app launched by the share), then sent as an `openLink` action (`{command, text}`) on the session channel; `media_session::Action::OpenLink` → `link::share`: resolution off the main thread, target kept (`SHARED`) then `open-link` event; the UI takes it through `take_shared_link` on the event, at startup and at sign-in (`openSharedLink`), only when signed in. Since 0.5.85 (#435), `open-link` is also listened to on desktop: clicking a new release notification goes through `link::open` (`feed` target added, see [`system.md`](system.md)). Text without a link: toast. **Tapped links** (0.4.93, #203): second intent filter of `ShareActivity`, `VIEW` + `BROWSABLE`, `https` on `tidal.com`, `www.tidal.com`, `listen.tidal.com`, paths `/browse/<type>/` and `/<type>/` of the types the app opens only (track, album, artist, playlist, mix; videos stay in the browser); `intent.dataString` follows the same path as sharing. No `autoVerify` (domain that is not ours): since Android 12 the system sends these links to the browser until the user has given them to the app ("Open by default" › "Add links" › tidal.com). `LinkHandling.kt` (through `Bridge`): state read through `DomainVerificationManager` (`isLinkHandlingAllowed` and host `tidal.com` `SELECTED` / `VERIFIED`) and opening `ACTION_APP_OPEN_BY_DEFAULT_SETTINGS`. Commands `link_handling` (`{enabled}`, `null` on desktop and before Android 12) and `open_link_settings`. Settings › Application › TIDAL links (`.setting-row.tidal-links`, Android only), state reread on return (`visibilitychange`). Preview: `?route=settings&tab=app&platform=android[&links=1]`. - **List performance** (#88): `player.state` is a `$state.raw` replaced on every `player-state` (~4 Hz); every reader of `state` is woken on every position. Measured in the preview (`?route=playlist&long=5000`, loaded machine, hidden pane): cost of a `player-state` 44 ms → 0.5 ms with 5,000 rows, forced layout after opening 2.2–3.5 s → 0.1 s; what remains is creating the 5,000 rows (~1 s on an idle machine, ~3.5 s loaded), without virtualization for now. Measuring: the hidden pane slows `setTimeout` / `setInterval` and freezes `requestAnimationFrame`, wait through `MessageChannel`; import the app's modules by their real URL (Vite adds `?t=` to modified modules, an `import('/src/…')` gives another instance).

## Language (0.4.17, #7)

- **Choice proposed in the issue**: no i18n library, a typed home-made module (two languages). Setting Settings › Appearance › Language: `system` (default, confirmed by the user: an English Windows switches the app to English on update), `fr`, `en` (`UiSettings::language`).
- **Effective language decided on the Rust side** (`i18n.rs`): the setting, otherwise the Windows display language (`GetUserDefaultUILanguage`, French if the primary language is French, English otherwise), `java.util.Locale.getDefault()` through JNI on Android (#186, `android::system_language`: Android does not set `LANG`), `LANG` elsewhere (`from_code`, tested). Applied at startup before the player, then by `set_language` (returns the effective language) and `set_ui_settings`. `language` command for the UI. Atomic global state: read by messages and the `locale`, never by logic.
- **Backend messages**: `i18n::tr(fr, en)` for a fixed text, `trf!("… {}", "… {}", args)` for a formatted text, usable in `thiserror`'s `#[error("{}", trf!(…, .0))]`. Command errors, toasts and typed errors (`TidalError`, `MpvError`…) are translated; the technical details they carry (context of a `Decode`) and `tracing` logs are not translated: written in English since 0.5.97 (many still in French, translated when their file is touched), since logs and crash reports are read by contributors. Unit tests run in French (default language, never changed outside `live_locale`).
- **TIDAL content**: `i18n::tidal_locale()` (`fr_FR` / `en_US`) for the home page, the feed and `pages/mix`. Home row keys do not depend on the language (verified): the customized layout stays valid. The home page and the feed keep their module cache with the language and reload if it changes; library mixes keep their subtitles until "Refresh".
- **UI**: `lib/i18n.svelte.ts` exposes `t` (proxy to the current language's dictionary: `t.player.play`, `t.common.tracks(n)`), `locale()` and `num()` for `Intl`, `initLanguage` / `setLanguage`. Strings stored per area in `lib/i18n/<area>.ts`, each with `fr` (source) and `en: typeof fr`: a missing key makes `pnpm check` fail. Plurals and texts with values = functions. Read in a template or a `$derived`, `t` follows the language change without reloading. Do not name a loop variable or a parameter `t` in a component that imports it. Key notation per language (Do / C). Proper theme names stay (Studio, Atelier, Acidwave); Verre de mer → Seaglass, Surréalisme → Surrealism.
- The language buttons reuse `.cache-sizes` / `.cache-size` (with `.languages` / `.language`), already overridden by Acidwave and Surrealism.
