# Interface

Notes d'implémentation de Seaglass, lues à la demande (index dans [`CLAUDE.md`](../CLAUDE.md)). L'UI n'a aucune logique métier : elle affiche l'état reçu du backend et envoie des commandes.

## Navigation, réglages et aperçu

- **UI** : navigation par pile de routes (`lib/stores/nav.svelte.ts`) sans URL, bouton Retour dans l'en-tête. Lire un titre d'une liste met toute la liste en contexte ; « Aléatoire » passe par `play_tracks(…, shuffle: true)`, le backend choisit le titre de départ.
- **Réglages UI** : `ui_settings` / `set_ui_settings`, JSON dans `kv` (`ui.settings`). Thème inconnu refusé à la désérialisation.
- **Couleur d'album** : `vibrantColor` → `AlbumRef::color` / `AlbumSummary::color`, filtrée en `#rrggbb` (elle part dans le CSS). L'UI la pose en `--album` sur `<html>`.
- **Chaîne audio** (`SignalPath.svelte`) : source → mpv → sortie, verdict « Fréquence native » / « Rééchantillonné » / « Profondeur réduite » / « Compressé ». En mode partagé, Windows peut encore mixer : c'est dit dans le détail du verdict, pas présenté comme bit-perfect.
- **Raccourcis** : Espace (lecture/pause), Ctrl+K ou `/` (recherche), Échap (fermer), Alt+← (retour), Ctrl+, (réglages), Ctrl+↑ / Ctrl+↓ (volume ±5), F11 (plein écran, bureau). **Plein écran** (0.4.51, #131, `commands/window.rs`, bureau seulement) : `set_fullscreen(bool)` sur la fenêtre `main` renvoie l'état relu ; événement `fullscreen` émis sur `WindowEvent::Resized` quand l'état change, commande `fullscreen` pour l'état initial (`lib/stores/window.svelte.ts`). Indépendant de « En lecture » (choix de l'issue), qui a un bouton `.fullscreen-toggle` à côté de Fermer. Échap sort d'abord du plein écran, puis ferme « En lecture ». Rien sur Android.
- **Prévisualisation sans Tauri** : `pnpm dev` puis `http://127.0.0.1:1420/?theme=studio&route=album&nowplaying=1` (paramètres : `theme`, `route` dont `settings`, `mix` et `radio`, `tab` (onglet de bibliothèque ou section des réglages `appearance|playback|app`), `nowplaying`, `queue`, `paused`, `loggedout`, `authfail` (session non reprise, nouvel essai automatique), `update`, `autostart`, `volume=60|muted`, `accent=ff5c8a`, `lyrics=1|plain|none`, `trackinfo=1`, `truncated=1|nototal`, `hiresedition=<album>`, `hiresoffer=<album>`, `hirestwin=1`, `lang=fr|en`, `autoradio=1`, `mpv=cpu|stopped`, `manual=1`, `long=<n>` (playlist et titres likés de n titres synthétiques), `platform=android` (mise en page tactile), `ticks=1` (`player-state` à 4 Hz, `playbackTick()` exporté pour une mesure), `sleep=30|track`, `device=dac|missing`, `normalization=track|album`, `fullscreen=1`, `slow=<ms>` (ouverture de playlist ralentie)). Plusieurs serveurs en parallèle : `pnpm vite --port <n> --strictPort`. Svelte 5 délègue `change` et `input` : un événement créé par script doit avoir `bubbles: true`. Données de `src/lib/mock/fixtures.json`, généré par `cargo test dump_ui_fixtures -- --ignored` (gitignoré : contient la bibliothèque du compte). La branche factice est éliminée du build de production (`import.meta.env.DEV`).
- **Piège Vite** : à deux reprises, après des éditions de fichiers par script, le CSS d'un composant est resté périmé alors que son JS était à jour (règles absentes du `?svelte&type=style`). Redémarrer `pnpm tauri dev` et vider `node_modules/.vite` règle le problème. Le panneau de navigateur intégré, quand il est masqué, gèle aussi les animations et le chargement différé des images : pour une capture, injecter `*{animation:none!important}`.
- **Tests du frontend** (#264, `pnpm test`, aussi dans la CI après `pnpm check`) : `vitest` reprend `vite.config.ts` (bloc `test`), donc le plugin Svelte compile les `.svelte.ts` et `i18n` / `platform` s'importent tels quels. Environnement `node`, sans DOM simulé : les événements sont des objets partiels, `swipe.test.ts` a une ligne factice (`EventTarget` + `classList` / `style`). Tests à côté du module (`src/lib/<module>.test.ts`), données dans `src/lib/testing/` ; les deux sont hors du bundle et ignorés par le contrôle de version. Changer de langue : `i18n.lang = "en"`, remis à `fr` dans `afterEach` (idem `platform.mobile`). Backend et navigation simulés par `vi.mock` (`links.test.ts`). Couvert : `trackOrder`, `format`, `playSource`, `links`, `reorder`, `swipe`, `touch-reorder` (globals du navigateur remplacés par `vi.stubGlobal`, `requestAnimationFrame` joué à la main). Piège : `Array.sort` est déjà stable, un test d'égalité du tri doit partir d'une liste qui n'est pas dans l'ordre d'origine.
- **CSP** (`tauri.conf.json`) : en plus de `default-src 'self'`, `base-uri 'none'`, `form-action 'none'` (les deux `<form>` font `preventDefault`) et `object-src 'none'`. Un nouvel hôte d'images va dans `img-src`.

## Pages et listes

- **Page Réglages** (#9, `views/Settings.svelte`) : route `settings`, sections Apparence / Lecture / Application. Entrées : barre latérale, bouton de l'en-tête, `Ctrl+,`. Accessible déconnecté (Retour ramène à la connexion). Plus de boîtes Apparence / À propos : `ThemePicker.svelte` et la section Application les remplacent.
- **Liens du projet** (0.4.71, #188, `commands/project.rs`) : « Code source » et « Signaler un bug ou proposer une idée » sous À propos (`.project-links`, boutons `.update-check`). Commande `open_project_page(page: repo | newIssue)`, URLs fixes côté Rust, ouvertes par `tauri-plugin-opener` (enregistré après l'instance unique, aucune permission côté UI). Le dépôt est public ; ouvrir une issue demande un compte.
- **File dans « En lecture »** (#20) : `components/QueueList.svelte`, partagé avec la vue File. Panneau replié par défaut, état de session `ui.nowPlayingQueue`. Toute navigation ferme la vue « En lecture ».
- **Accueil personnalisable** (#21, #22) : `commands/settings/home_layout.rs` (logique pure, testée), réglage `UiSettings::home { order, hidden }`, commandes `set_home_layout` (sections dans l'ordre de l'écran ; les absentes du flux gardent leur place) et `reset_home_layout`. `home` renvoie des `HomeSection` (avec `hidden`) : l'UI masque hors du mode « Personnaliser ». Masquer porte sur le type de section. Réordonner : Monter / Descendre (clavier, Android) et, sur le bureau, glisser-déposer d'une ligne (0.4.106, #246, `Reorder` de `lib/reorder.svelte.ts` comme la file, repère `.drop-before` / `.drop-after`). Sous Windows, le glisser HTML5 exige `"dragDropEnabled": false` sur la fenêtre (`tauri.conf.json`) : sinon Tauri capte les glisser-déposer pour le dépôt de fichiers et WebView2 ne livre plus `dragover` / `drop` (#290, valait aussi pour la file et les playlists). Sur Android, le glisser HTML5 ne marche pas au doigt : appui long (350 ms sans bouger de plus de 10 px) puis glisser, par l'action `touchReorder` de `lib/touch-reorder.ts` (#290) ; la ligne suit le doigt (`.touch-dragging`, `--drag-y`), `touchmove` est annulé après la saisie pour que la page ne défile pas, et elle défile seule près des bords. Le même `Reorder` place le repère et applique le déplacement (`commit`). **À la une** (0.4.71, #185) : l'album vient de tous les albums des sections affichées (dédoublonnés), tiré au hasard une fois par lancement (`featuredIndex`, `$state` du module de `Home.svelte`) ; bouton « Passer » (`.hero-skip`, à côté du bouton `.hero` dans `.hero-wrap`, au survol sur le bureau, toujours sur Android) ; masquable par la ligne « À la une » en tête de l'éditeur (`HomeLayout::featured_hidden`, commande `set_home_featured`, remis par `reset_home_layout`). Les albums les plus écoutés dans l'app passent en tête du tirage (#202, voir « Historique d'écoute » dans `lecteur.md`).
- **Titres likés** (0.4.62, #161) : boutons Lecture / Aléatoire au-dessus du filtre (`Library.svelte`, `.liked-header`), dans un `header .info .actions` pour que les thèmes les habillent comme ceux de `PageHeader` ; suivent le tri, pas le filtre ; masqués pendant la recherche dans la liste (#151). Sur Android, playlists et mixes sans numéros (#162) ; albums et top d'un artiste les gardent.
- **Filtre et tri des listes** (#1, #2, `lib/trackOrder.ts`, `components/TrackTools.svelte`) : présentation sur une liste déjà chargée, dans Playlist et Bibliothèque › Titres. Lire depuis une liste filtrée ou triée met en contexte la liste affichée, dans l'ordre affiché ; Lecture / Aléatoire de l'en-tête suivent le tri mais pas le filtre. `TrackList` accepte `positions` pour garder les numéros d'origine. Filtre non mémorisé ; tri mémorisé par liste depuis 0.4.37 (#93) : `UiSettings::sorts` (`{list, key, descending}`, `list` = uuid ou `likedTracks`), logique pure dans `commands/settings/sorts.rs` (testée : plus récent en tête, 200 listes au plus, le tri par défaut de la liste retire l'entrée), commande `set_list_sort(list, sort | null)` qui renvoie la liste enregistrée ; l'UI lit le tri à l'ouverture (`listSort`) et l'enregistre à chaque changement (`saveListSort`, binding par fonctions sur `TrackTools`).
- **Épingles** (0.4.6, #10, `commands/settings/pins.rs`, logique pure testée) : `UiSettings::pins`, liste ordonnée de `Pin` (`kind: playlist` avec uuid + titre, `mix` avec id + titre (0.4.118, #193), `likedTracks`, ou `later` pour l'onglet « Plus tard », 0.4.103, #244). Sur Android, les épingles sont les tuiles du mode conduite (`docs/android.md`). Libellé et page d'une épingle : `lib/pins.ts` ; clé : `pinKey` (`stores/ui.svelte.ts`). `set_pins` valide (uuid `8-4-4-4-12`, doublons retirés, 50 maximum) et renvoie la liste enregistrée. Bouton `PinButton` dans l'en-tête Playlist, Mix (pas les radios) et dans Bibliothèque › Titres ; section « Épinglés » sous Bibliothèque dans `Sidebar`. Le titre gardé est remis à jour à l'ouverture de la playlist. Backend factice : les arguments sont des proxys Svelte, un handler qui les renvoie doit les copier en JSON (`structuredClone` les refuse).
- **Liens collés** (0.4.75, #203, `commands/link.rs`, testé) : commande `open_link(text)` → `LinkTarget` (`album` avec `track` éventuel, `artist`, `playlist`, `mix`) ou `null`. Reconnaît `tidal.com/browse/<type>/<id>`, `tidal.com/<type>/<id>`, `www.` et `listen.tidal.com`, avec ou sans schéma, `/u`, paramètres, au milieu d'un texte de partage (2 000 caractères au plus) ; dernière paire valide du chemin (`album/1/track/2` = le titre). Seuls le type et un identifiant validé (numérique, uuid, id de mix) sortent. Un titre est résolu en son album (`tidal.track`) : la page s'ouvre avec le titre marqué et centré (`Route` `album` + `track`, `TrackList` `highlight`, `.row.highlighted`). UI (`lib/links.ts`) : Ctrl+V hors d'un champ (`onpaste` de la fenêtre, connecté seulement), collage dans la recherche, ou Entrée sur un lien dans la recherche. **Menu « Partager » d'Android** (0.4.78, #203, pas encore vérifié sur le S21) : `ShareActivity` du plugin (filtre `ACTION_SEND` `text/plain`, exportée, sans interface comme `NowPlayingActivity`) passe le texte à `Playback.share`, gardé dans `pendingShare` tant que Rust n'a pas branché la session (app lancée par le partage), puis envoyé en action `openLink` (`{command, text}`) sur le canal de la session ; `media_session::Action::OpenLink` → `link::share` : résolution hors du thread principal, cible gardée (`SHARED`) puis événement `open-link` ; l'UI la prend par `take_shared_link` à l'événement, au démarrage et à la connexion (`openSharedLink`), seulement connectée. Texte sans lien : toast. **Liens touchés** (0.4.93, #203) : second filtre d'intent de `ShareActivity`, `VIEW` + `BROWSABLE`, `https` sur `tidal.com`, `www.tidal.com`, `listen.tidal.com`, chemins `/browse/<type>/` et `/<type>/` des seuls types ouverts par l'app (track, album, artist, playlist, mix ; les vidéos restent au navigateur) ; `intent.dataString` suit le même chemin que le partage. Pas d'`autoVerify` (domaine qui n'est pas à nous) : depuis Android 12 le système envoie ces liens au navigateur tant que l'utilisateur ne les a pas donnés à l'app (« Ouvrir par défaut » › « Ajouter des liens » › tidal.com). `LinkHandling.kt` (par `Bridge`) : état lu par `DomainVerificationManager` (`isLinkHandlingAllowed` et hôte `tidal.com` `SELECTED` / `VERIFIED`) et ouverture de `ACTION_APP_OPEN_BY_DEFAULT_SETTINGS`. Commandes `link_handling` (`{enabled}`, `null` sur le bureau et avant Android 12) et `open_link_settings`. Réglages › Application › Liens TIDAL (`.setting-row.tidal-links`, Android seulement), état relu au retour (`visibilitychange`). Aperçu : `?route=settings&tab=app&platform=android[&links=1]`. Bureau : le copier-coller suffit (choix de l'utilisateur, Windows n'a pas d'équivalent pour les liens `https`).
- **Historique de recherche** (0.4.76, #211, `commands/search_history.rs`, logique pure testée) : `note_search_history(query)` enregistre une requête retenue (espaces réduits, en tête, doublon à la casse près remplacé, 20 au plus) dans `kv` (`search.history`) ; `search` n'y touche pas depuis la recherche pendant la frappe (#248). Commandes `search_history`, `remove_search_history(query)` et `clear_search_history`, qui renvoient la liste. Effacé à la déconnexion. UI : champ vide = « Recherches récentes » à la place des résultats (`.search-history`, `.search-history-item`, `.search-history-query`, `.search-history-remove` visible au survol, toujours sur Android, `.search-history-clear`) ; un clic relance la recherche. Aperçu : `?route=search` (trois entrées factices).
- **Recherche pendant la frappe** (0.4.105, #248, `Search.svelte`) : la requête part 400 ms après la dernière frappe, comme sur la page de la Jam ; un numéro de requête écarte les réponses arrivées dans le désordre ; les résultats précédents restent affichés, estompés (`.results.stale`), jusqu'à l'arrivée des suivants. Un lien collé n'est pas cherché. Seule une requête retenue entre dans l'historique : Entrée, une recherche récente cliquée, ou un clic dans les résultats (`onpointerdowncapture`), sinon chaque préfixe tapé y finirait.
- **Menu contextuel** (0.4.11, #52) : un seul `components/ContextMenu.svelte` monté dans `App`, ouvert par `openMenu` (`lib/stores/menu.svelte.ts` : position, entrées, `from` qui reprend le focus, `owner` mis en évidence). Entrées d'un titre dans `lib/trackMenu.ts` : Lire, Lire ensuite, Ajouter à la file (ou Retirer de la file), Radio, Aller à l'album, une entrée par artiste, Copier le lien (`tidal.com/browse/track/<id>`). Ouvert au clic droit sur une `TrackRow` ou par son bouton « … » (aussi sur les lignes sans actions de la file) ; clavier : ↑/↓, Début/Fin, Entrée, Échap, Tab ; touche Menu / Maj+F10 (pas de coordonnées : menu sous l'élément focalisé). Fermé sur clic ailleurs, molette, redimensionnement, perte de focus et changement de page. Le menu natif de WebView2 est bloqué partout sauf dans les champs de texte et sur une sélection (copier). Le `{#each}` des entrées est sans clé : en runes, un `each` à clé garde l'ancien élément pour une même clé, un menu rouvert par-dessus gardait ses anciennes entrées. « Ajouter à une playlist » et les likes : voir « Écritures dans la bibliothèque » dans `tidal.md`.
- **Performances des listes** (#88) : `player.state` est un `$state.raw` remplacé à chaque `player-state` (~4 Hz) ; tout lecteur de `state` est réveillé à chaque position. Ce qui ne change qu'au changement de titre ou d'état vit dans des champs à part écrits seulement par `apply` (`currentTrack`, `currentTrackId`, `playing`, `advancing`), qui ne préviennent que si la valeur change ; un `$derived` ne suffit pas (Svelte revérifie chacun de ses lecteurs à chaque changement de la source). `apply` garde aussi par référence les champs objets inchangés (`track`, `stream`, `output`, `volume`, `hiresOffer`, `sleep`). Une liste lit `player.currentTrackId`, jamais `player.state`. Progression et paroles passent par `followPosition` (dans un `$effect`) : boucle `requestAnimationFrame` seulement si la position avance, une mise à jour par état reçu sinon ; texte du temps recalculé à la seconde. `.row` de `TrackRow` en `content-visibility: auto` (`contain-intrinsic-size: auto 52px`) : la peinture est contenue, rien d'une ligne ne doit déborder de son cadre (vérifié en Risographie, Bauhaus, Cyberpunk, Acidwave). Mesuré dans l'aperçu (`?route=playlist&long=5000`, machine chargée, panneau masqué) : coût d'un `player-state` 44 ms → 0,5 ms avec 5 000 lignes, mise en page forcée après ouverture 2,2–3,5 s → 0,1 s ; reste la création des 5 000 lignes (~1 s machine libre, ~3,5 s chargée), sans virtualisation pour l'instant. Mesure : le panneau masqué ralentit `setTimeout` / `setInterval` et gèle `requestAnimationFrame`, attendre par `MessageChannel` ; importer les modules de l'app par leur URL réelle (Vite ajoute `?t=` aux modules modifiés, un `import('/src/…')` donne une autre instance).

## Langue (0.4.17, #7)

- **Choix proposé dans l'issue** : pas de bibliothèque i18n, un module maison typé (deux langues). Réglage Réglages › Apparence › Langue : `system` (défaut, confirmé par l'utilisateur : un Windows en anglais passe l'app en anglais à la mise à jour), `fr`, `en` (`UiSettings::language`).
- **Langue effective décidée côté Rust** (`i18n.rs`) : réglage, sinon langue d'affichage de Windows (`GetUserDefaultUILanguage`, français si la langue principale est le français, anglais sinon), `java.util.Locale.getDefault()` par JNI sur Android (#186, `android::system_language` : Android ne pose pas `LANG`), `LANG` ailleurs (`from_code`, testé). Appliquée au démarrage avant le lecteur, puis par `set_language` (renvoie la langue effective) et `set_ui_settings`. Commande `language` pour l'UI. État global atomique : lu par les messages et la `locale`, jamais par la logique.
- **Messages du backend** : `i18n::tr(fr, en)` pour un texte fixe, `trf!("… {}", "… {}", args)` pour un texte formaté, utilisables dans `#[error("{}", trf!(…, .0))]` de `thiserror`. Erreurs des commandes, toasts et erreurs typées (`TidalError`, `MpvError`…) sont traduits ; les détails techniques qu'elles portent (contexte d'un `Decode`) et les journaux `tracing` restent en français. Les tests unitaires tournent en français (langue par défaut, jamais changée hors `live_locale`).
- **Contenu TIDAL** : `i18n::tidal_locale()` (`fr_FR` / `en_US`) pour l'accueil, le fil et `pages/mix`. Les clés de ligne de l'accueil ne dépendent pas de la langue (vérifié) : la disposition personnalisée reste valable. L'accueil et le fil gardent leur cache de module avec la langue et rechargent si elle change ; les mixes de la bibliothèque gardent leurs sous-titres jusqu'à « Actualiser ».
- **UI** : `lib/i18n.svelte.ts` expose `t` (proxy vers le dictionnaire de la langue courante : `t.player.play`, `t.common.tracks(n)`), `locale()` et `num()` pour `Intl`, `initLanguage` / `setLanguage`. Textes rangés par domaine dans `lib/i18n/<domaine>.ts`, chacun avec `fr` (source) et `en: typeof fr` : une clé manquante fait échouer `pnpm check`. Pluriels et textes avec valeurs = fonctions. Lu dans un gabarit ou un `$derived`, `t` suit le changement de langue sans rechargement. Ne pas nommer `t` une variable de boucle ou un paramètre dans un composant qui l'importe. Notation des tonalités par langue (Do / C). Les noms propres de thèmes restent (Studio, Atelier, Acidwave) ; Verre de mer → Seaglass, Surréalisme → Surrealism.
- Les boutons de langue réutilisent `.cache-sizes` / `.cache-size` (avec `.languages` / `.language`), déjà surchargés par Acidwave et Surréalisme.
